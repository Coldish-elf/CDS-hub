# CDS-hub documentation

> **Цель репозитория**  
> Создать единый, легко поддерживаемый набор LaTeX‑файлов, которые можно использовать для подготовки. \
> Каждый новый участник может быстро сделать свой вклад, не создавая собственный макет с нуля.

---

## 📐 Стиль и конвенции

### Определения

В начале должно быть `\hiddensection{Определения}`

```tex
%%% Определение X.
\phantomsection\label{sec_DefinitionX}
\begin{definition}[Как неожиданно и неочевидно, но, вероятно, тут должно быть название определения. Да.]
    ...определяем определение...
    \begin{note}
        ...дополняем определённое определение...
    \end{note}
\end{definition}
```

### Формулировки

В начале файла должно быть `\hiddensection{Формулировки}`

```tex
%%% Формулировка X.
\phantomsection\label{sec_FormulationX}
\begin{formulation}[Никогда такого не было, и вот опять - тут должно быть название формулировки.]
    ...формулируем формулировку...
    \begin{note}
        ...дополняем сформулированную (или сформулированную не до конца) формулировку...
    \end{note}
\end{formulation}
```

### Доказательства

В начале файла должно быть `\hiddensection{Доказательства}`

```tex
%%% Доказательство X.
\phantomsection\label{sec_ProofX}
\begin{proof}[Неожиданно и неочевидно - тут должно быть название чего-то, что будет доказываться.]
    ...формулируем что-либо доказывающееся...
    \begin{note}[amber]
        ...доказываем сформулированное ранее...
        \begin{note}
            ...сюда можно добавить какое-то пояснение, желательно в тему (опционально)...
        \end{note}
    \end{note}
\end{proof}
```

### Любые другие секции

Также должны содержать в начале файла `\hiddensection{Название секции}`. \
Также вы можете использовать любые цвета, которые сочтёте нужными.

```tex
%%% Название секции.
\phantomsection\label{sec_SectionName}} % пожалуйста, используйте PascalCase
\begin{formulation}[Название секции]
    Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut labore et dolore magna aliqua.
    \begin{note}
        Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut labore et dolore magna aliqua.
    \end{note}
\end{formulation}
```

## ℹ️ Общие требования

### Требования к файлам в общем и целом

1. Каждый файл должен оправдывать своё существование.
2. Классификация по файлам должна быть структурированной и интуитивно понятной.
3. Необходимо максимально придерживаться выбранного нами стиля кода. Давайте сделаем `.tex` чище и понятнее для всех!

### 📁 Структура дочерней папки, в которую вы вносите свой вклад

```
CDS-hub/
├─ Discrete-Mathematics/
│   ├─ colloquium-1 /                  # домашняя директория одного коллоквиума
│   │   ├─ definitions/                  # все определения должны быть тут
│   │   │   ├─ definition-1.tex          # определения
│   │   │   ├─ ...
│   │   │   └─ definitions.tex           # основной файл для объединения всех определений
│   │   ├─ formulations/                 # все формулировки должны быть тут
│   │   │   ├─ formulation-1.tex         # формулировки
│   │   │   ├─ ...
│   │   │   └─ formulations.tex          # основной файл для объединения всех формулировок
│   │   ├─ proofs/                       # все доказательства должны быть тут
│   │   │   ├─ proof-1.tex               # доказательства
│   │   │   ├─ ...
│   │   │   └─ formulations.tex          # основной файл для объединения всех формулировок
│   │   └─ colloquium1-dm.tex          # основной документ
│   └─ ...
├─ Linear-Algebra/
│   └─ ...
└─ ...
```

**Важно** - каждый файл в директории `parts` **не содержит преамбулу**.
Он только вставляется в `colloquium.tex`.  

> **TIP:** \
> В случае добавления **необходимых** новых комманд - задумайтесь; возможно, стоит добавить её \
> для общего удобства в `stylefile.sty`, или, по крайней мере, поговорить об этом. \
> Любые улучшения приветствуются!

## 📄 Как пользоваться

### 1️⃣ Скопируйте репозиторий к себе

```bash
git clone https://github.com/Coldish-elf/CDS-hub.git
cd CDS-hub
```

### 2️⃣ Создание правильной дочерней файловой структуры

Для создания правильной структуры папки Вы **можете использовать скрипт** `generate-structure.py`. \
Также её структура описана выше! Пожалуйста, следуйте ей, в ином случае ваш pull request не будет одобрен и будет отправлен на доработку.

### 3️⃣ Добавьте свой контент в `pages/filename.tex`

* Необходимо начинать файл с "магического комментария" - как правило это помогает компилятору понять, какой из файлов является корневым; стоит заметить,  что магический комментарий будет добавлен автоматически при использовании скрипта для генерации.
* Весь материал оформляется через среды **definition**, **formulation**, **proof** (см. ниже).  
* Для заметок используйте среду `note`. Цвет можно задать в квадратных скобках: `[purple]`, `[amber]` и т.д. \
Все возможные существующие цвета описаны несколько ниже; впрочем, спасибо, что читаете это.

### 4️⃣ Откройте основной файл `colloquium-xx-x.tex` и убедитесь, что путь к шаблону указан правильно

```tex
% !TeX root = colloquium-xx-x.tex

\input{../../stylefile.sty}   % <- корректный путь до stylefile.sty
```

> Если вы работаете в другом каталоге, просто скорректируйте относительный путь.

Небольшое примечание. \
`stylefile` необходим для того, чтобы сделать шаблон **ОБЩИМ**.
Наиболее удобное решение для унификации файлов как по стилю, так и с точки зрения иерархии.
Ведь здорово, когда все функции есть в одном месте!

### 5️⃣ Компиляция

Мы используем `latexmk`.

```bash
latexmk -pdf colloquium.tex
```

## 🛠️ Что включено в `stylefile.sty`

* Подключение пакетов: `amsmath`, `amssymb`, `graphicx`, `hyperref`, `xcolor` и др.
* Определения окружений
* Цвета для заметок:
  * green (используется для указания дополннительной информации)
  * amber (используется только для доказательств)
  * purple
  * teal
  * blue
  * red
* Макросы для создания титульной страницы: `\createtitle`.
* Поддержка светлой/темной темы через `\def\darkmode{}` и команду `\createcolormode`.

## 🤝 Краткое руководство для людей, желающих отредактировать что-либо

1. **Создавайте ветку** (`git checkout -b edit/...`).
2. **Добавляйте или редактируете** необходимые файлы (один коллоквиум - одна ветка).
3. **Проверяйте** компиляцию: `latexmk -pdf colloquium.tex`. Если PDF открывается без ошибок - ваш PR готов.
4. **Объясняйте изменения** в описании Pull Request (почему добавили новую формулировку, исправили орфографию и т.п.).
5. **Ссылайтесь на материалы**: при внесении правок помимо объяснения изменений было бы неплохо сослаться на источник. \
***Базовым минимумом*** считается частичная ссылка на какой-либо общедоступный конспект в том случае, если исходник достаточно структурирован. \
***Роскошным максимумом*** считается скриншот с выпиской (нет, не из психбольницы) того или иного исправления, с прикреплением ссылки на документ.
